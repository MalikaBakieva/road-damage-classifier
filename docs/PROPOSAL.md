# Technical Proposal

> Brief §6 — completed **before** full implementation, as required.

| Decision / Question | Response |
|---|---|
| **ML problem formulation** | **Supervised single-label image classification on road-surface patches.** Two heads trained independently on the same crops: a **binary** head (`damaged` / `not_damaged`) as the production signal, and a **5-class** head (`not_damaged`, `longitudinal_crack`, `transverse_crack`, `alligator_crack`, `pothole`) for routing detail. Deliberately *not* framed as object detection: the client needs "does this report deserve an inspection, and roughly what kind?", which classification answers with far less annotation sensitivity and a much simpler, more defensible evaluation. Multi-label was rejected because RDD2022's per-box labels give clean single labels once cropped, and multi-label metrics would obscure the imbalance story. |
| **Proposed baseline** | Three tiers, so improvement is measured rather than asserted. **(0) Majority class** — predicts the most frequent label; establishes the accuracy floor and demonstrates why accuracy is the wrong metric (~90 % accuracy, macro-F1 ≈ 0.47 on binary). **(1) Classical CV** — grayscale + edge-density / Laplacian-variance / local-contrast features into logistic regression; a genuinely informative baseline because cracks are edge-rich. **(2) Fine-tuned ResNet-18** — the reference deep model that must beat both. Any proposed improvement has to beat tier 2 on *validation* macro-F1 to be adopted. |
| **Main modeling approach(es) to investigate** | **Transfer learning with ImageNet-pretrained CNNs** — the labelled set is small relative to the task and crops are texture-heavy, so fine-tuning dominates training from scratch. Backbones compared via `configs/*.yaml` (`model.backbone`): `resnet18` (reference, fast), `efficientnet_b0` (better accuracy/FLOP), `convnext_tiny` (strongest, slowest). Schedule: 1 epoch of frozen-backbone linear probing to settle the randomly-initialised head, then full fine-tuning with a 10× higher head learning rate, AdamW, cosine decay. Augmentation targets the documented failure modes — random-resized crop, horizontal flip, ±8° rotation, brightness/contrast/saturation jitter, occasional Gaussian blur, random erasing. Not pursued: training from scratch (insufficient data), object detection (out of scope), heavy ensembling (cost outweighs benefit at prototype scale). |
| **Data splitting / validation strategy** | **Grouped, stratified, image-level split — 70 / 15 / 15.** Grouping key is `image_id`, so every crop from one photo lands in exactly one split; this is the single most important guard against the leakage identified in Discovery. Stratification is on the image's dominant damage class, so rare classes (potholes) appear in all three splits. Seeded (`seed: 42`) and enforced by a unit test. Validation drives early stopping and model selection; **the test split is evaluated exactly once**, by `rdc.evaluate`. Grouped k-fold CV is the natural extension if variance estimates are needed, at ~5× training cost. |
| **Primary evaluation metric(s) and why** | **Primary: macro-F1.** The classes are heavily imbalanced and every damage type matters to the client, so the metric must not be dominated by the majority class. Accuracy and micro-F1 both are — a model that never predicts `pothole` still scores ~90 % accuracy. Macro-F1 averages per-class F1 with equal weight, so ignoring a class is immediately visible. **Secondary:** recall on `damaged` (a missed defect costs the department more than a false alarm routed to triage); per-class precision/recall/F1; balanced accuracy; ROC-AUC; row-normalised confusion matrix (to see *which* classes are confused); expected calibration error (the API exposes a confidence threshold, so an over-confident model would route nothing to human review); and a coverage/accuracy threshold sweep so the department can pick an operating point from evidence. |
| **Expected inference input** | A single road photograph uploaded as multipart form-data: JPEG, PNG, WebP or BMP, ≤ 10 MB, any resolution (resized to 224×224 internally). **No metadata is required or used** — GPS, timestamp and camera model are frequently absent from citizen submissions, and depending on them would break inference in exactly the cases the client cares about. Non-images, corrupt files, empty uploads and oversized files are rejected with a specific HTTP status and an actionable message, never a stack trace. |
| **Expected inference output** | JSON: `predicted_class`, `confidence`, `is_damaged`, `damage_probability`, full `probabilities` map, `top_k`, `needs_human_review` (true when confidence < threshold), `priority` (`high`/`medium`/`low`/`review`/`none`, mapping potholes to the top of the queue), model and image metadata, `inference_ms`, and a `disclaimer` stating the output is triage support and not an engineering safety assessment. A batch endpoint returns per-item success/failure so one bad file cannot fail a whole upload. |
| **Main technical risks / assumptions** | **R1 — Domain shift.** Trained on daytime vehicle-mounted dashcam imagery; citizen phone photos are closer, differently angled and often at night or in rain. *Mitigation:* aggressive geometric/photometric augmentation, an explicit robustness evaluation under simulated dark/bright/blur/rotation/downscale shifts (`reports/*/robustness.json`), and a documented recommendation to fine-tune on a few hundred locally collected photos before deployment. **R2 — Class imbalance.** *Mitigation:* inverse-frequency loss weighting (default) or a weighted sampler, both config-selectable; macro-F1 as the selection metric. **R3 — Label noise in negatives.** Unannotated regions may contain missed damage, capping achievable recall. *Mitigation:* documented as a known ceiling; negatives sampled only from the road surface, not sky or buildings. **R4 — Crack subtypes are visually similar**, so multiclass macro-F1 will be materially lower than binary. *Mitigation:* binary is the production scope; multiclass is reported honestly with its confusion matrix. **R5 — Over-trust by users.** *Mitigation:* confidence threshold with human-review routing, disclaimer on every response, and scope language in the UI. **R6 — Reproducibility drift.** *Mitigation:* seeded splits, config saved alongside every checkpoint, MLflow tracking, pinned dependencies, Docker image, CI that runs the full pipeline. **Assumptions:** images are roughly road-facing and the damage is visible in the frame; the department accepts a human-in-the-loop for low-confidence cases; RDD2022's licence permits this use. |
